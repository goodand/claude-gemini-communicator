# Anti-patterns — Skill 제작 시 하지 말 것

## 절차 관련

- **동기 없이 스킬 제작** → Phase -1에서 반복 문제·목표·비목표를 먼저 정의
- **자료 조사 없이 Phase 1 진입** → Phase 0 먼저
- **reference 저장 없이 knowledge_base부터 작성** → reference 원자료를 먼저 저장하고 그다음 KB로 정리
- **기능 범위 경계 없이 착수** → 비목표를 명시하지 않으면 scope creep 발생
- **정적 검증만으로 완료** → Phase 5-2 tmux+Codex 실전 테스트 필수
- **디버깅 결과를 기록하지 않음** → Phase 5-3 troubleshooting 패턴 저장
- **계획을 암묵적으로 처리** → 복잡한 작업은 plans/에 명시적으로 저장
- **Codex 활용 안 함** → 로컬 코드 분석은 Codex에게 위임하여 효율 극대화
- **smoke test 없이 완료 선언**

## SKILL.md 관련

- SKILL.md에 커맨드 예시 나열 → **references로 이동**
- reference 읽지 않고 SKILL.md 초안 그대로 사용
- reference 내용을 SKILL.md에 중복 기재
- reference 링크 없이 "자세한 내용은 참고" → **"(→ `references/X.md` 섹션명)" 정확한 포인터**

## Scripts 관련

- **스크립트 없이 워크플로우만 서술** → 반복 패턴은 scripts/로 추출
- **스크립트에 검증 로직 없음** → exit code + stderr 경고로 결과 추적 가능하게
- **stdout에 진행 메시지 섞기** → stdout은 데이터만, 나머지는 stderr로
- `str | None` 같은 Python 3.10+ 전용 문법 사용 → `from __future__ import annotations`
- scripts/ 사용법을 SKILL.md에 상세 설명 → **`--help`로 위임**
- **`_load()` 함수가 str/dict 둘 다 반환** → `_load_text()` / `_load_json()` 분리 (→ `practical-lessons.md` §1)
- **래퍼 함수 check=False로 존재 확인** → returncode 직접 검사 (→ `practical-lessons.md` §2)
- **mutation 후 validation** → validate-before-mutate 위반 시 객체 오염 (→ `practical-lessons.md` §4)

## 문서-코드 정합성 관련

- **문서에 규칙을 쓰고 validate에 미구현** → 문서 규칙 = validate 검증 항목 (→ `practical-lessons.md` §3)
- **상태 다이어그램과 전이 테이블 불일치** → 머신-리더블 레지스트리가 있으면(예: `dispatch_contract_v0_1.json`) 레지스트리가 canonical source이고 코드/문서는 projection(`_shared/scripts/audit_contract_sync.py`로 감사); 레지스트리가 없을 때만 코드의 `VALID_TRANSITIONS`이 canonical source (→ `practical-lessons.md` §9)
- **reference 3개 이상인데 교차 검증 없이 구현** → Consistency Checklist를 구현 전에 작성 (→ `practical-lessons.md` §10)
- **정합성 평가용 checklist 없이 구현용 checklist부터 작성** → 구현용 checklist는 consistency checklist를 operationalize한 문서여야 함
- **scripts/나 구현 파일을 만들고 TDD 파일을 만들지 않음** → `scripts/test_*.py` 또는 `tests/test_*.py`를 같이 작성

# Review Convergence Consistency Checklist

- [ ] product intent and non-goals were locked before detailed reading
- [ ] repo files were classified by product role, not by arbitrary folder order
- [ ] every finding includes severity, file, and expected correction
- [ ] Codex closure review rereads current code-state instead of trusting prior session state
- [ ] sibling fields in the same structural class were checked after each patch
- [ ] residual 1-2 issue threshold was evaluated before opening another handoff round
- [ ] async/API-surface rewrites were escalated to specialist verification instead of being silently absorbed
